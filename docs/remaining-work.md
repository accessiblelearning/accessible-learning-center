Owner constraints: $0 additional spending; no new service provisioning or billing; public login off until explicit authorization. The current account/admin screens are fictional previews, not a live account system.

## Can continue without waiting for full-site hands-on testing

1. **Command Practice teaching.** Continue replacing generic advanced explanations with command-specific examples. Check application/OS context and official shortcut mappings. Review remaining repeated actions for intentional recall versus duplication. Keep the concise main prompt and optional explanation.
2. **Topic Mission depth.** Expand scenario variety beyond the first tested example for Chrome, Excel, PowerPoint, VoiceOver and displays. Continue reviewing focus changes, recovery, current-step hints and protected key entry across existing missions. Preserve stable identifiers and completion history.
3. **Reporting and progress data.** Connect the now-demonstrated WPM/accuracy view to real account-owned session data when authorized infrastructure is ready. Capture practice date, lesson, hand path, mode, speed, accuracy and time practiced; preserve individual attempts and separate imported/learner-reported history from verified assessments. Add date ranges, comparable-practice trends, more than one page of history and learner-facing reports. Best scores alone are insufficient for improvement trends.
4. **Inactive account implementation.** Build the maintained-provider verification adapter, learner sign-in/sign-up/recovery flows, session expiry/logout handling, recovery errors, abuse protection and accessibility. This can be developed with local/fictitious fixtures; external activation remains blocked pending explicit owner approval.
5. **Saved progress and import.** Implement cross-device/offline sync and safe retries, shared-computer account switching, consent-based import review, detailed keyboard session and quiz adapters, and stable Command Practice progress. Retain the three independent 50-lesson typing paths and original local records. Private Braille requires its separate private adapter/access review.
6. **Administration and privacy.** Connect the sample admin workflows only after server authorization is ready; complete pagination, aggregate reporting, secure administrator setup, account support/recovery, data export/deletion and retention rules. Keep audited changes and never expose passwords.
7. **Curriculum refinement.** Continue review of Braille teaching consistency, recall spacing, word/sentence difficulty and timing; retain introduced-symbol restrictions. Preserve the existing 48-lesson private package unless a reproduced defect or specific teaching improvement warrants an update. Preserve all 50 lessons in each typing path and refine cues from learner reports.
8. **Ongoing QA.** Add regressions for reproduced issues in keyboard navigation, speech requests, layout, scoring, completion, progress and certificates. Review any new authentication changes separately for security. Automated passes are scoped evidence, not a guarantee of no bugs.

## Needs targeted human/device feedback

- JAWS/NVDA and Mac VoiceOver/Safari: spoken feedback, focus and real shortcut conflicts.
- Physical left-hand-only and right-hand-only reach/cues on the full keyboard.
- Braille: six-key rollover, dot readability, narration pace, recall spacing and whether the instructions are understandable.
- Low-vision use with preferred magnification, contrast and screen size.

Use short representative tasks, not repeated whole-site testing. Record the page, expected action, actual result, device/browser/screen reader and keys pressed.
