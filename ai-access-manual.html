Source-Grounded Research, Visual Assistance, Screen Readers, Braille, Verification, Privacy, and Human Escalation

Current product name: Google renamed NotebookLM to Gemini Notebook on July 16, 2026. This manual keeps NotebookLM in the title for familiarity while teaching the current Gemini Notebook product.

Purpose: This manual teaches source-grounded research with Gemini Notebook, visual assistance with Be My Eyes and Be My AI, and a practical framework for safe AI-assisted access.

Core principle: AI can increase independence, but it is not an infallible authority. Verify important details and escalate to an authoritative source or trusted human when an error could cause significant harm.

How to Use This Manual

  • Practice first with public documents, ordinary household objects, and non-sensitive photos.

  • Use Gemini Notebook citations to return to the original source rather than trusting a summary alone.

  • Do not use Be My AI for sensitive personal or financial information.

  • Use a live volunteer, company agent, trusted person, or professional when AI uncertainty matters.

  • Protect privacy before sharing a screen, camera view, clipboard image, document, speech output, or braille display.

  • Ask AI what it directly observed versus what it inferred.

  • For high-stakes information, the authoritative source or qualified human is the final verifier.

Part 1 - AI-Assisted Access: The Big Picture

Tool Best role
Gemini Notebook Source-grounded research and learning from documents you select.
Be My AI AI-generated descriptions of photos, screens, image files, and clipboard images.
Be My Eyes volunteer Live human visual assistance through one-way video and two-way audio.

Independence: Choosing the right tool is part of independence. AI is not automatically better than OCR, a screen reader, or a human.

Part 2 - NotebookLM Is Now Gemini Notebook

  • Google renamed NotebookLM to Gemini Notebook on July 16, 2026.

  • It remains a standalone research product.

  • Existing notebooks and shared links continue through the rebrand.

  • Gemini Notebook chat is grounded in notebook sources; Gemini app conversations using notebooks may also use web search and other tools.

Part 3 - Create a Notebook and Add Sources

3.1 Create a Notebook

What you will learn: Build a research workspace from selected sources.

Before you begin: Use a Google account and non-sensitive practice material.

Exactly how to do it

  1. Open the current Gemini Notebook website.
  2. Activate Create notebook or the new-notebook control.
  3. Give the notebook a descriptive name.
  4. Find Add source.
  5. Choose a source type.
  6. Upload or add the source.
  7. Wait for processing to complete.
  8. Review the Sources panel and source guide.

What should happen: The notebook contains a processed source that can be used in chat.

If that does not happen: If import fails, check file size/type, permissions, copy protection, or source availability.

Practice: Create a notebook with one public PDF and one public webpage.

3.2 Add Several Related Sources

What you will learn: Create a stronger research collection.

Before you begin: A notebook is open.

Exactly how to do it

  1. Activate Add source.
  2. Add another relevant source.
  3. Repeat until you have several sources.
  4. Rename unclear source titles when the interface allows.
  5. Keep unrelated topics in separate notebooks.

What should happen: The notebook contains a focused source set.

If that does not happen: If answers become unfocused, deselect irrelevant sources or split the project into multiple notebooks.

Practice: Build a three-source practice notebook.

Part 4 - Source Types and Limits

  • Current supported sources include PDF, DOCX, TXT, Markdown, CSV, PPTX, Google Docs, Google Slides, Google Sheets, images, audio, web URLs, public captioned YouTube videos, pasted text, ePub, and eligible Google Play Books ebooks.

  • Current published local-upload limit is up to 200 MB and 500,000 words per source.

  • Free accounts currently support up to 50 sources per notebook; paid plans may allow more.

  • Google Slides currently supports up to 100 slides as a source.

  • YouTube import uses the transcript/captions, not the visual video content.

Rights: Only upload or import content you are authorized to use.

Part 5 - Chat with Sources and Use Citations

5.1 Ask a Grounded Question

What you will learn: Get an answer tied to source material.

Before you begin: At least one source is processed.

Exactly how to do it

  1. Move to the chat prompt.
  2. Ask a specific question about the source material.
  3. Send the question.
  4. Read the response.
  5. Move to an inline citation.
  6. Activate the citation.
  7. Read the cited passage and surrounding context.

What should happen: You can trace important claims back to the source.

If that does not happen: If the question is outside the selected sources, Gemini Notebook may say it cannot answer.

Practice: Verify three claims through citations.

Screen-reader citation strategy: Do not depend on visual hover previews. Activate the citation and read the source passage directly.

Part 6 - Source Selection, Notes, and Source Guides

6.1 Limit a Question to Selected Sources

What you will learn: Compare documents or reduce irrelevant context.

Before you begin: The notebook has multiple sources.

Exactly how to do it

  1. Review source checkboxes in the Sources panel.
  2. Select only the sources relevant to the question.
  3. Return to chat.
  4. Ask the question.
  5. Repeat with another source subset and compare the answer.

What should happen: The response reflects the selected source set.

If that does not happen: If unwanted sources remain active, recheck selection state.

Practice: Compare two sources on the same issue.

  • Source Guides summarize individual sources.

  • Notes can contain your own text or saved chat responses.

  • Current Google Help says written notes are editable; saved-response notes are not editable once created.

  • Notes can be converted into sources when you intentionally want future chat grounded on them.

Part 7 - Audio and Video Overviews

7.1 Generate an Audio Overview

What you will learn: Create a podcast-style spoken summary.

Before you begin: Use a notebook with suitable sources.

Exactly how to do it

  1. Open Studio.
  2. Find Audio Overview.
  3. Select sources/customization options if offered.
  4. Enter a focus prompt if desired.
  5. Generate the overview.
  6. Play it.
  7. Use play/pause, skip, and speed controls.
  8. Return to source citations to verify surprising claims.

What should happen: A spoken overview is generated from your sources.

If that does not happen: If an important claim seems wrong, verify it in the source rather than trusting the audio.

Practice: Generate one overview and verify three claims.

Video Overviews: Video Overviews are visually rich. For nonvisual access, use source-grounded chat, available text, or request a separate description of the visuals.

Part 9 - Mind Maps and Accessible Alternatives

9.1 Turn a Mind Map into Structured Text

What you will learn: Use the conceptual relationships without depending on a visual diagram.

Before you begin: A Mind Map exists.

Exactly how to do it

  1. Ask chat for the main branches as headings.
  2. Ask for subtopics as nested lists.
  3. Ask it to state cross-branch relationships in sentences.
  4. Verify the concepts against the selected sources.

What should happen: You receive a linear, screen-reader-friendly representation.

If that does not happen: If a relationship is missing, ask for an explicit list of connections.

Practice: Convert one mind map into a nested outline.

Part 10 - Exporting and Mobile Use

  • Reports can be exported to Google Docs.

  • Data Tables can be exported to Google Sheets.

  • Edits in exported Docs/Sheets do not synchronize back to the notebook.

  • Sharing permissions do not automatically carry over to exported files.

  • The mobile app supports a subset of desktop features. Google recommends desktop for the full experience.

  • Mobile supports key source types such as PDF, websites, YouTube, audio, and copied text, plus Audio/Video Overviews; some Studio features remain desktop-only.

Part 11 - Gemini Notebook with Screen Readers and Braille

  • Use headings and landmarks to move among Sources, Chat, and Studio when exposed by the web app.

  • Use button/form-control navigation for Add source, checkboxes, prompt fields, generation controls, and menus.

  • JAWS/NVDA users may need to switch between browse and focus/application modes for interactive controls.

  • VoiceOver users may need to interact with grouped web controls.

  • Braille works through the active screen reader; test output, input, and routing.

  • Prefer textual reports and citation-linked source passages when a visual artifact is inefficient to access.

Recovery: Press Escape to close a popup, return to a top-level heading or landmark, then re-enter the panel you need.

Part 12 - Gemini Notebook Privacy and Sharing

  • Google states that files added to notebooks and chats in Gemini Notebook are not used directly to train foundational generative AI models unless you provide feedback.

  • Data handling can differ when a notebook is used inside the Gemini app.

  • Shared notebooks expose permitted notebook content to collaborators.

  • Exported Docs/Sheets have independent sharing settings.

  • Deleted notes currently cannot be recovered.

  • Do not upload confidential or regulated information unless your organization authorizes it.

Part 13 - What Be My Eyes Is

  • Be My Eyes connects blind and low-vision users with live sighted volunteers, participating company support, and Be My AI.

  • Volunteer calls use one-way video from the user and two-way audio.

  • Be My AI accepts photos and returns detailed AI-generated descriptions.

  • Be My AI is available on iOS, Android, and Windows desktop.

  • The Service Directory can connect users with participating companies for product-specific help.

Part 14 - Call a Sighted Volunteer

14.1 Get Live Visual Help

What you will learn: Use a human when real-time camera guidance is useful.

Before you begin: Choose a non-sensitive task and stable internet.

Exactly how to do it

  1. Open Be My Eyes.
  2. Open Get Support.
  3. Choose Call a Volunteer.
  4. Wait for the volunteer to answer.
  5. State the task clearly.
  6. Tell the volunteer how you are holding the phone.
  7. Move the camera slowly in response to directions.
  8. Ask for confirmation of important details.
  9. End the call when finished.

What should happen: A volunteer provides live verbal visual assistance.

If that does not happen: If the volunteer cannot help, end politely and call again or use a specialized company service.

Practice: Practice centering a household label.

Part 15 - Use Be My AI on Mobile

15.1 Take a Picture for Description

What you will learn: Get an AI description of an ordinary object or scene.

Before you begin: Use a non-sensitive object.

Exactly how to do it

  1. Open Be My Eyes.
  2. Open the Be My AI tab.
  3. Activate Take picture.
  4. Point the rear camera at the subject.
  5. Hold still and take the picture.
  6. Wait for the description.
  7. Read or listen to the result.
  8. Use Ask more for a specific follow-up.

What should happen: Be My AI returns a description within the conversation.

If that does not happen: If it is vague, retake with better light, distance, framing, or angle.

Practice: Describe a package and ask where a control or label is located.

Internet: Be My AI requires an internet connection.

Part 16 - Follow-Up Questions and Multiple Pictures

16.1 Ask More

What you will learn: Turn one description into an interactive visual task.

Before you begin: A mobile Be My AI description is open.

Exactly how to do it

  1. Activate Ask more.
  2. Ask one specific question.
  3. Send it.
  4. Read the answer.
  5. Add another picture if the mobile interface offers it.
  6. Compare what is directly visible across the images.

What should happen: The conversation stays focused on the visual subject.

If that does not happen: If the model starts guessing, ask: What can you see directly and what are you inferring?

Practice: Use two angles of the same harmless object.

Desktop difference: Current Windows desktop guidance uses one image per chat; start a new desktop chat for a new image.

17.1 Describe a Harmless Screen

What you will learn: Use AI as a supplement to screen-reader navigation.

Before you begin: Close unrelated private windows first.

Exactly how to do it

  1. Open Be My Eyes desktop.
  2. Choose Describe your screen.
  3. Allow the capture.
  4. Read the description.
  5. Ask a focused question such as: Which dialog is open and what buttons are visible?
  6. Return to the original app.
  7. Use your screen reader to locate the named control.

What should happen: The AI description gives orientation while the screen reader remains the control/navigation tool.

If that does not happen: If the screen contains sensitive information, cancel and use a safer method.

Practice: Describe a Windows Settings screen and locate one named button with your screen reader.

Part 18 - Service Directory and Be My Eyes Workplace

  • Service Directory connects users with participating organizations for specialized product/service assistance.

  • Availability depends on region and business hours.

  • Be My Eyes Workplace is enabled by an employer or organization.

  • Current Workplace features include Workplace AI, Workplace Reader, and Workplace Connect with trusted company assistance/screen sharing where configured.

  • Follow employer confidentiality and data-handling rules.

Part 19 - Be My Eyes Privacy and Sensitive Information

  • Do not show passports, driver licenses, or other government ID.

  • Do not share bank, credit-card, insurance, or other financial information.

  • Do not expose Social Security or government identification numbers.

  • Do not share usernames, passwords, access keys, or security-question answers.

  • Avoid sensitive medical information in ordinary Be My AI use.

  • Remember that live volunteers can see the camera view and hear the conversation.

Current data statement: Be My Eyes states that it does not train AI models on Be My AI submissions, questions, or responses and does not allow its AI provider to train on that data. Current help says ordinary AI descriptions are retained for 30 days unless the user chooses to save specific images/conversations.

Part 21 - Better Image and Screen Descriptions

21.1 Ask Better Visual Questions

What you will learn: Get actionable spatial information instead of a generic description.

Before you begin: Use a harmless image.

Exactly how to do it

  1. Ask for an overall description.
  2. Ask for spatial layout: top/bottom, left/right, foreground/background.
  3. Ask for exact visible text.
  4. Ask which details are unreadable or uncertain.
  5. Ask where the object/control is located relative to a tactile landmark.
  6. Retake the picture if glare, angle, distance, or cropping limits the answer.

What should happen: The answer becomes more useful for independent action.

If that does not happen: If the AI changes its answer, treat the disputed detail as uncertain and escalate.

Practice: Describe one control panel using orientation language.

Part 22 - Documents, Charts, Forms, and Tables

  • Use Gemini Notebook when a document can be uploaded and cited.

  • Use OCR/document readers for straightforward text recognition.

  • Use AI to explain chart/layout structure, but verify exact values against the data.

  • For forms, prefer accessible electronic forms and official assistance; do not let AI infer legal or financial answers.

  • Ask AI to convert visual tables into row-by-row structured text.

  • Verify signatures, dates, totals, account numbers, dosage, and legal terms directly.

Part 23 - Everyday Visual Tasks

23.1 Labels and Packaging

  • Take a straight, close photo with good light.

  • Ask what product is shown.

  • Ask for exact visible text.

  • Ask where information appears on the package.

  • Photograph another side instead of expecting one image to show everything.

23.2 Clothing

  • Ask for garment type, color, pattern, orientation, and visible damage.

  • Use a second photo when matching items.

  • Exact color is lighting-dependent; use a human when shade matching matters.

23.3 Appliances

  • Ask for the arrangement of buttons/dials.

  • Identify tactile landmarks before pressing anything.

  • Use the official manual for safety-related controls.

  • Do not let AI guess burner, electrical, gas, medical-device, or other hazardous settings.

Part 24 - High-Stakes Limits and Human Escalation

  • Medication, dosage, pills, medical devices, or medical records.

  • Financial accounts, payment instructions, cards, checks, or tax documents.

  • Legal forms, contracts, court documents, or government identification.

  • Electrical panels, gas controls, fire/smoke hazards, traffic, machinery, or dangerous tools.

  • Identity verification or accusations about a person.

  • Anything where an error could be difficult to reverse.

Escalation order: Use an authoritative accessible source first, then a trained professional/company representative or trusted human. AI may help formulate questions but should not be the final verifier.

Part 25 - Deepfakes, Misidentification, and False Confidence

  • AI can misidentify people, objects, text, colors, locations, and relationships.

  • Generated or edited images can look authentic.

  • Voice cloning can imitate relatives, executives, or public figures.

  • Do not use AI image description as proof of identity.

  • Ask what is directly observed versus inferred.

  • Verify important media through original sources, direct contact, and independent evidence.

Part 26 - Screen Reader and Braille Privacy

  • Speech can be overheard; use headphones for sensitive work.

  • Braille cells can expose information to nearby braille readers.

  • Clipboard history may retain copied descriptions or document text.

  • Screen-description tools capture what is visible; close unrelated private windows first.

  • Camera assistance can reveal mail, addresses, people, screens, and surroundings unintentionally.

  • Lock devices when finished.

Pre-capture question: What else is visible that I did not intend to share?

Part 27 - Troubleshooting

27.1 Gemini Notebook Answer Seems Wrong

What you will learn: Return to the source rather than arguing with the summary.

Before you begin: A claim conflicts with your understanding.

Exactly how to do it

  1. Open the citation.
  2. Read the cited passage and surrounding context.
  3. Check which sources are selected.
  4. Repeat the question with only the most relevant source.
  5. Ask the model to separate direct statements from inference.

What should happen: The source or interpretation problem becomes clear.

If that does not happen: If the source itself is unreliable, add a stronger source.

Practice: Correct one ambiguous answer.

27.2 Gemini Notebook Cannot Answer

What you will learn: Check whether the information exists in the selected sources.

Before you begin: Chat says the answer is unavailable.

Exactly how to do it

  1. Review selected sources.
  2. Search for the key term in the source.
  3. Rephrase using the source terminology.
  4. Add a relevant source if the information is genuinely missing.

What should happen: Chat answers when appropriate source material exists.

If that does not happen: Do not ask source-grounded chat to invent missing information.

Practice: Ask one answerable and one unanswerable question.

27.3 Be My AI Is Vague or Inconsistent

What you will learn: Improve the image and narrow the question.

Before you begin: The visual answer is not trustworthy enough.

Exactly how to do it

  1. Ask which detail is uncertain.
  2. Retake with better light.
  3. Change distance.
  4. Change angle.
  5. Ask one question at a time.
  6. If inconsistency remains, call a volunteer or trusted person.

What should happen: The task becomes clearer or is escalated safely.

If that does not happen: Repeated confident answers are not proof.

Practice: Retake one image three ways.

27.4 Volunteer Cannot See the Detail

What you will learn: Use deliberate camera orientation.

Before you begin: A live volunteer says the view is unclear.

Exactly how to do it

  1. State how you are holding the phone.
  2. Ask for one direction at a time: left/right/up/down/closer/farther.
  3. Move slowly.
  4. Pause after each movement.
  5. Ask when the target is centered.

What should happen: The volunteer can guide the camera more effectively.

If that does not happen: Stop if the task requires unsafe one-handed operation.

Practice: Practice centering a printed label.

27.5 Screen Reader Focus Is Lost

What you will learn: Return to structural navigation.

Before you begin: An AI web panel or popup changed focus.

Exactly how to do it

  1. Press Escape to close menus/dialogs.
  2. Use heading navigation.
  3. Use landmarks/regions if supported.
  4. Use edit-field navigation to find chat.
  5. Switch browse/focus/application mode if direct interaction is required.

What should happen: You return to a known part of the interface.

If that does not happen: After major product updates, explore labels instead of relying on old visual position.

Practice: Practice opening and closing a Studio panel.

Website practice procedures

These procedures preserve the Accessible Learning Center's original guided practice alongside the expanded manual.

Basic how-tos

Navigate an AI website

What you will learn: Complete navigate an ai website independently with keyboard or screen-reader feedback.

Before you begin: Open the relevant application or device screen and use a fictional, public, or nonprivate practice item.

Exactly how to do it

Keyboard commands: Tab and Shift+Tab move through controls. Enter activates links and buttons. Space changes checkboxes. H moves by heading and B moves by button in JAWS and NVDA browse mode.

  1. Open the tool and confirm its name and active account.
  2. Press H to review page headings.
  3. Press E or F in supported screen readers to find an edit field.
  4. Type a short prompt using only public, fictional, or authorized information.
  5. Submit it, then return to headings or browse mode to locate the response.
  6. Read the complete response before acting.

What should happen: A named prompt field, a submit control, and a structured response.

If that does not happen: Press Escape once, check the focused control with Insert+Tab or NVDA+Tab, and navigate by landmarks or headings.

Practice: Repeat navigate an ai website with a second safe practice item, then explain the commands you used.

Ask for a useful image description

What you will learn: Complete ask for a useful image description independently with keyboard or screen-reader feedback.

Before you begin: Open the relevant application or device screen and use a fictional, public, or nonprivate practice item.

Exactly how to do it

Keyboard approach: Find Upload, Add image, or Take picture by button navigation.

  1. Remove private documents, addresses, faces, credentials, and medical information unless sharing is authorized.
  2. Activate the image control and choose the intended image.
  3. Verify the filename before submitting.
  4. Ask a focused question such as, “Describe the controls from top to bottom,” or “Read the expiration date and state any uncertainty.”
  5. Save the answer only after checking important details another way.

What should happen: The intended item, setting, or result is available and can be verified before you continue.

If that does not happen: Cancel the upload and confirm the image format, connection, and permissions.

Practice: Repeat ask for a useful image description with a second safe practice item, then explain the commands you used.

Before you begin: Open the relevant application or device screen and use a fictional, public, or nonprivate practice item.

Exactly how to do it

Keyboard commands: Use H for headings, B for buttons, and Tab or Shift+Tab through dialogs.

  1. Open NotebookLM and activate Create new notebook.
  2. Enter a descriptive notebook name.
  3. Activate Add source.
  4. Choose the source type and select only an authorized document or public link.
  5. Wait for processing and verify that the source name appears in the source list.

If that does not happen: Do not add the source again until you check the source list and any processing alert.

  3. Open each citation.
  4. Read enough text before and after the cited passage to understand context.
  5. Mark each claim supported, unsupported, or uncertain.
  6. Use only supported claims in your work.

Exactly how to do it

Keyboard approach: Return to the prompt field and ask follow-up questions that isolate one detail at a time.

  1. Ask the tool to separate visible observations from interpretation.
  2. Ask where an item is located using clock-face or top-to-bottom language.
  3. Ask it to repeat exact text, numbers, or colors and state uncertainty.
  4. Verify medication, money, identity, navigation, safety, and legal information with a trusted person or authoritative source.

What should happen: The intended item, setting, or result is available and can be verified before you continue.

If that does not happen: State what remains unknown. Never convert an uncertain AI description into a confident instruction.

Write a safer prompt

What you will learn: Complete write a safer prompt independently with keyboard or screen-reader feedback.

Before you begin: Open the relevant application or device screen and use a fictional, public, or nonprivate practice item.

Exactly how to do it

Keyboard command: Ctrl+A selects the current prompt text; Ctrl+C copies; Ctrl+V pastes.

  1. State the task and desired format.
  2. Supply only the minimum authorized context.
  3. Ask the tool to identify assumptions and uncertainty.
  4. Request citations when the answer depends on sources.
  5. Review the prompt for private information before submitting.

What should happen: The intended item, setting, or result is available and can be verified before you continue.

If that does not happen: Shorten the request and ask one question at a time.

Practice: Repeat write a safer prompt with a second safe practice item, then explain the commands you used.

Quick command list

  • Tab / Shift+Tab: next or previous control
  • Enter: activate or submit
  • Escape: close a menu or dialog
  • H: next heading in JAWS or NVDA browse mode
  • B: next button in JAWS or NVDA browse mode
  • E: next edit field in JAWS or NVDA browse mode
  • Insert+Tab / NVDA+Tab: identify focused control
  • Ctrl+A / Ctrl+C / Ctrl+V: select all / copy / paste
