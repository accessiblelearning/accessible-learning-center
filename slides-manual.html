First-time keyboard guide

Use this short routine before following the Google Slides Manual procedures. It explains exactly how the keyboard directions in this manual work.

Press a single key

  1. Find the named key without pressing it if possible.
  2. Press and release the key one time. Do not hold it unless the step specifically says to hold it.
  3. Stop and listen to the full screen-reader announcement before pressing another key.

Press a keyboard combination

  1. When a command contains a plus sign, such as Ctrl+S, hold down the first key.
  2. While continuing to hold the first key, press and release the final key once.
  3. Release the first key. The plus sign is not a key and should not be pressed.
  4. Listen for the expected result described in the procedure. If nothing changes, verify that the correct application or webpage has focus and try the command once more.

Press a sequence of keys

  1. When keys are separated by commas or the word “then,” press and release them in order instead of holding them together.
  2. After each key, listen for a menu, tab, control, or new screen before continuing.
  3. If the announcement does not match the step, press Escape once to close the current menu or dialog and restart that procedure.

Know which navigation key to try

  • Tab and Shift+Tab: move forward and backward among buttons, links, fields, and other controls.
  • Arrow keys: move inside menus, lists, groups of choices, text, and many screen-reader reading views.
  • Enter: opens the selected item or activates the focused command.
  • Space: activates many buttons and checks or clears checkboxes. In a text field, Space types a space.
  • Escape: cancels or closes the current menu, list, or dialog without intentionally accepting a change.

Verify before moving on

  1. Listen for the window, page, or application name so you know where focus is.
  2. Perform only one numbered step.
  3. Compare what the screen reader announces with the “What should happen” information in the procedure.
  4. If the result is wrong, stop. Use the procedure’s recovery directions, Escape to cancel, or Ctrl+Z to undo when that command is supported.
  5. Continue only after you can identify the result. Save completed work with Ctrl+S whenever the application supports saving.

First complete independent workflow

This rehearsal joins existing procedures into one uninterrupted session without repeating their directions. Follow the linked procedure when a step names it, then return here for the next verification.

Safety check: Confirm the active account, workspace, audience, and privacy level before entering, uploading, sharing, or sending information.

  1. Open Google Slides Manual and wait until its name, starting screen, or connected-device status is announced.
  2. Choose a fictional, public, disposable, or instructor-provided practice item. Do not use private client, student, medical, financial, or account-recovery information.
  3. Open 1. Open Slides and Enable Screen-Reader Support. Read its “What you will learn,” “Before you begin,” keyboard-command, and expected-result information before pressing anything.
  4. Complete that procedure one numbered action at a time. After each key, stop and identify what changed before continuing.
  5. State the result aloud or record it in a practice note. If it differs from “What should happen,” use that procedure’s recovery directions before advancing.
  6. Continue directly to 2. Navigate Slides, Filmstrip, Canvas, and Menus without closing the application or device session. First confirm that focus, account, file, book, conversation, or project context is still correct.
  7. Complete the second procedure and verify the resulting name, state, location, permission, value, or content. Do not rely only on a success sound.
  8. Save or synchronize when the product supports it. Wait for the completed state before disconnecting a device, closing a browser, or switching accounts.
  9. Continue to 3. Create Slides with Built-In Layouts and Titles. Use the exact command listed there; if the command varies by model or version, use Keyboard Help, the product’s shortcut list, or the linked official reference instead of guessing.
  10. Introduce one harmless recoverable error, such as opening the wrong menu or moving focus away. Press Escape once, identify the active window or device area, and return to the correct step.
  11. Review the finished practice item from its beginning. Confirm its title or filename, structure, content, destination, sharing state, and saved or synchronized status as applicable.
  12. Close and reopen the item or return to it from the product’s main screen. The workflow is complete only when you can locate it and verify the same result independently.

Success standard: Complete all three linked tasks, explain the commands used, recover from the practice error, and locate the finished result without another person directing the next key.

No-cost course rule

This course must not require a purchase, subscription, paid trial, payment card, or new paid service. LibreOffice is free and open source. Google Docs editors and Microsoft 365 for the web have free account-based options, but internet access, account rules, storage limits, and available features can differ.

Use an employer-approved program and account for workplace information. A free personal account is not automatically approved for client or organizational data.

Accessibility comes before feature count

Before choosing a program, test the actual work tasks with the learner’s preferred screen reader, Braille display, magnification, browser zoom, color settings, and keyboard. Confirm that focus is announced, controls have useful names, editing feedback is understandable, and essential tasks do not require a mouse.

  • Use descriptive headings, real lists, clear table headers, meaningful links, alternative text, sufficient contrast, and logical reading order.
  • Do not communicate meaning only through color or visual position.
  • Run the program’s accessibility checker when available, but also perform a keyboard and screen-reader review.
  • Keep an original editable file before exporting PDF or converting formats.

Native and exchange formats

LibreOffice native formats
ODT for Writer, ODS for Calc, and ODP for Impress preserve LibreOffice editing features.
Microsoft exchange formats
DOCX, XLSX, and PPTX are often required by employers or instructors using Microsoft 365.
Other formats
CSV carries plain spreadsheet data without formulas or formatting. PDF is useful for fixed-layout review but may be harder to edit and must be checked for accessibility.

Save the native version first. Then save or download a separate exchange copy and review it in the receiving program whenever possible.

JAWS, Narrator, and NVDA

Interfaces vary by program and update. Use Tab and Shift+Tab for controls, arrow keys within menus and lists, Enter or Space to activate, Alt or F10 for menus when supported, Ctrl+S to save, Ctrl+O to open, and Ctrl+Z to undo. Listen for the current control name and state instead of memorizing screen position.

  • JAWS: Use Insert+T for the window title, Insert+Tab for focused-control information, and Insert+1 for Keyboard Help.
  • NVDA: Use NVDA+T for the title, NVDA+Tab for focus, and NVDA+1 for Input Help.
  • Narrator: Use Caps Lock+T for the title and Caps Lock+1 for Input Learning. Toggle Scan Mode only when the application or webpage requires it.

Browser-based editors may have their own screen-reader-support setting and keyboard shortcuts. Read the current official help before changing screen-reader modes.

Compatibility review

  1. Keep an untouched native copy.
  2. Create a separate DOCX, XLSX, PPTX, CSV, or PDF copy.
  3. Read every heading, cell range, slide title, link, table, image description, formula result, note, and page or slide count.
  4. Check fonts, spacing, page breaks, charts, animations, formulas, comments, and accessibility metadata.
  5. Correct the native file and export again rather than repeatedly converting the same exchange copy.

Never promise perfect compatibility without testing the actual document in the receiving software.

Privacy, accounts, and sharing

Use fictional or public information in these lessons. Do not upload client records, medical or disability information, passwords, financial data, or confidential workplace material. For cloud tools, confirm the active account and sharing permission before entering content. For local tools, back up files to an approved location.

Basic procedure

1. Open Slides and Enable Screen-Reader Support

What you will learn: Open a blank presentation, enable current screen-reader support if needed, and identify the filmstrip, canvas, and menus.

Before you begin: Open the application and a fictional, instructor-provided, or nonprivate practice file. Save a separate working copy before making major changes.

Exactly how to do it

  1. Read the Google Slides manual sections on accessibility, screen readers, file formats, and compatibility.
  2. Open Google Slides and confirm the window title or browser tab, active file, and current account when applicable.
  3. Navigate the main controls using only the keyboard. Record the labels announced by JAWS, Narrator, or NVDA.
  4. Open a blank presentation, enable current screen-reader support if needed, and identify the filmstrip, canvas, and menus.
  5. Save frequently in the program’s preferred editable format. If working in a browser, confirm that changes are saved before closing.
  6. Review the work from the beginning using keyboard and screen-reader navigation. Correct unclear structure, labels, or data.
  7. Create a separate Microsoft-compatible or requested exchange copy. Do not overwrite the editable original.
  8. Open or re-import the exchange copy when possible and compare content, formatting, formulas, notes, links, and accessibility.
  9. Write a short compatibility report naming anything that changed and how it was corrected.
  10. Save the submission using the filename slides-Lesson-1.pptx.

Screen-reader help: Use Tab and Shift+Tab for controls and listen to the current accessible name. JAWS users can use Insert+Tab, NVDA users NVDA+Tab, and Narrator users Scan Mode commands when appropriate. Application and web-editor commands may differ after updates.

What should happen: You can complete the procedure and verify the result using the keyboard, your screen reader, or your braille display.

If that does not happen: Press Escape to leave an unexpected menu or dialog, confirm the active window and keyboard focus, then repeat one step at a time. Use Undo when a reversible content change occurred.

Practice: Open a blank presentation, enable current screen-reader support if needed, and identify the filmstrip, canvas, and menus.
