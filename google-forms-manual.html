How to Use This Manual

  • Create a disposable practice form first.

  • Use Tab/Shift+Tab and Forms shortcuts while editing.

  • JAWS: Virtual Cursor off; NVDA: Browse Mode off; VoiceOver: use direct interaction as needed.

  • Press Ctrl+/ to open the current shortcut panel.

  • Preview the form as a respondent before publishing it.

Part 1 - What Google Forms Is

  • Create surveys, registrations, questionnaires, and quizzes.

  • Responses can be viewed in Forms or linked to Google Sheets.

  • Forms can contain questions, sections, titles/descriptions, images, and videos.

  • Published forms expose question titles and sections as headings for easier screen-reader navigation.

Part 2 - Open/Create a Form

2.1 Create a Blank Form

What you will learn: Open a new form.

Keyboard command: Press Ctrl+L or Alt+D (Command+L on Mac), type forms.new, and press Enter. Use Tab/Shift+Tab to move through editor controls and edit fields.

Before you begin: Sign in to the intended Google account.

Exactly how to do it

  1. Press Ctrl+L or Alt+D.
  2. Type forms.new.
  3. Press Enter.
  4. Wait for the editor.
  5. Move through top controls with Tab.
  6. Find the form title field and enter a descriptive title.

What should happen: A blank form opens and is saved automatically.

If that does not happen: If another Google account opens, switch before adding private questions.

Practice: Create a form named Accessibility Practice Survey.

Part 3 - Screen Reader Setup

Task Command / Method
JAWS Press JAWS+Z until Virtual Cursor is off while editing the Form application.
NVDA Press NVDA+Space to turn Browse Mode off while editing.
VoiceOver Interact with editor controls; use standard form/edit-field navigation and direct interaction.
Shortcut panel Ctrl+/ on Windows/ChromeOS; Command+/ on Mac.

Published form: When taking/previewing a published form, screen-reader heading navigation is useful because titles, sections, and questions are exposed as headings.

Part 4 - Editor Interface

  • Questions tab: question construction.

  • Responses tab: submitted data.

  • Settings tab: collection, presentation, quiz, and response options.

  • Top controls: theme, preview, publish/send, More.

  • Focused question/item editor: title field, type selector, options, required toggle, item actions.

Settings shortcut: Current Forms documentation lists Ctrl+E on Windows/ChromeOS and Command+E on Mac to move focus to the Settings tab.

Part 5 - Add Questions

5.1 Insert a Question

What you will learn: Add a new question by keyboard.

Keyboard command: From a non-edit field in the Forms editor, press Ctrl+Shift+Enter (Command+Shift+Enter on Mac) to insert a question. Use Tab/Shift+Tab through question title, type, options, and Required controls.

Before you begin: Focus a non-edit field in the editor.

Exactly how to do it

  1. Press Ctrl+Shift+Enter.
  2. Move to the question-title edit field.
  3. Type the question.
  4. Move to the question-type control.
  5. Choose a type.
  6. Add answer options when required.
  7. Set Required if appropriate.

What should happen: A new question is added to the form.

If that does not happen: If Ctrl+Shift+Enter inserts a browser action, ensure focus is inside Forms and screen-reader browse mode is off.

Practice: Create three questions.

Part 6 - Question Types

  • Short answer: brief text.

  • Paragraph: longer text.

  • Multiple choice: one option.

  • Checkboxes: multiple options.

  • Dropdown: one selection from a compact list.

  • File upload: respondents upload files; account/organization restrictions apply.

  • Linear scale: rating scale.

  • Multiple-choice grid / checkbox grid: matrix questions; use carefully for accessibility.

  • Date and Time: structured date/time input.

Accessibility: Simple question types are usually easier to complete than complex grids. Use a series of ordinary multiple-choice questions when a grid does not add real value.

Part 7 - Required Questions and Validation

  • Use Required only when the answer is genuinely necessary.

  • Response validation can enforce number/text/length patterns.

  • Explain the required format in the question or description; do not rely only on an error after submission.

Part 8 - Titles, Descriptions, Images, and Video

Task Command / Method
Insert title/description Ctrl then I then H sequence in current shortcut list
Insert image Ctrl then I then P
Insert video Ctrl then I then V

Accessible media: Do not make an image/video the only source of essential instructions. Provide equivalent text/captions/transcript when needed.

Part 9 - Sections and Branching

9.1 Add a Section

What you will learn: Split a long form into manageable groups.

Keyboard command: From a non-edit field, hold Ctrl and press I then B (Mac: hold Command and press I then B). Use Tab/Shift+Tab to the section title/description fields.

Before you begin: Focus a non-edit field.

Exactly how to do it

  1. From a non-edit field, hold Ctrl and press I, then B. On Mac, hold Command and press I, then B.
  2. Type a descriptive section title.
  3. Add a short description if useful.
  4. Move related questions into that section.

What should happen: Respondents encounter a clearly named section break.

If that does not happen: If the form becomes too fragmented, combine small sections.

Practice: Create two sections with meaningful titles.

Branching: Forms can route respondents to sections based on certain question answers. Test every path before publishing so no user reaches a dead end.

Part 10 - Move, Duplicate, and Delete Items

Task Command / Method
Move item up Ctrl+Shift+K
Move item down Ctrl+Shift+J
Duplicate focused item Ctrl+Shift+D
Delete item Alt+Shift+D

Safety: Duplicate before experimenting with a complex item; delete only after reading the focused question title.

Part 11 - Settings

  • Collect email addresses when appropriate and permitted.

  • Limit to one response only when account sign-in is appropriate.

  • Control whether respondents can edit after submitting.

  • Set presentation/confirmation message.

  • Quiz settings add points, answer keys, feedback, and grade-release choices.

Part 12 - Preview and Publish

Task Command / Method
Preview Ctrl+Shift+P
Publish Ctrl+Enter

12.1 Preview Like a Respondent

What you will learn: Test accessibility before publishing.

Keyboard command: From a non-edit field, press Ctrl+Shift+P (Command+Shift+P on Mac). In the published preview, use your screen reader heading command to move question-by-question and Tab/Shift+Tab through answer controls.

Before you begin: The draft has several questions.

Exactly how to do it

  1. Press Ctrl+Shift+P.
  2. In the preview, switch your screen reader back to normal webpage reading if needed.
  3. Navigate by headings through the form.
  4. Complete every question type.
  5. Trigger one validation error intentionally.
  6. Submit only if using a disposable form.

What should happen: You experience the form the way respondents do.

If that does not happen: If headings or labels are unclear, return to the editor and rewrite them.

Practice: Preview every form before publishing.

Part 13 - Share a Form

  • Publish/Send controls can create a responder link, email distribution, or embedding options depending on current interface.

  • Use descriptive link text when sharing by email/document.

  • Check whether sign-in or domain restrictions prevent intended respondents from accessing the form.

Part 14 - Responses

  • Responses tab shows Summary, Question, and Individual views where available.

  • Stop accepting responses when the collection period ends.

  • Do not publish response summaries when answers contain private information.

Part 15 - Link Responses to Sheets

15.1 Create Response Spreadsheet

What you will learn: Analyze responses in Google Sheets.

Keyboard command: From a non-edit field, press Ctrl+E (Command+E on Mac) to move to the tab area, then use Left/Right Arrow to reach Responses. Use Tab/Shift+Tab to the Link to Sheets/Create spreadsheet control and press Enter.

Before you begin: At least one response exists or the form is ready to collect.

Exactly how to do it

  1. From a non-edit field, press Ctrl+E (Command+E on Mac), then use Left/Right Arrow to move to Responses.
  2. Press Tab/Shift+Tab until Link to Sheets/Create spreadsheet is announced, then press Enter.
  3. Choose a new or existing spreadsheet.
  4. Confirm.
  5. Open the linked Sheet and review headers.

What should happen: Each response becomes structured spreadsheet data.

If that does not happen: Changing question structure after data collection can complicate the response sheet; document changes.

Practice: Link a disposable practice form.

Part 16 - Quizzes and Grading

  • Turn on Make this a quiz in Settings.

  • Set answer keys and point values.

  • Use current grading shortcuts such as Ctrl+Shift+C for correct and Ctrl+Shift+I for incorrect where supported.

  • Provide written feedback, not only a score, when explanation helps.

  • Test accommodations and locked-mode requirements before high-stakes assessment.

Part 17 - Accessible Form Design

  • Use short, descriptive form and section titles.

  • Write one clear question per prompt.

  • Place instructions before the question they govern.

  • Avoid color-only instructions.

  • Avoid complex grids unless necessary.

  • Explain format expectations for dates, IDs, numbers, or file uploads.

  • Use accessible linked documents/media.

  • Preview with a screen reader before publishing.

Part 18 - Screen Reader Workflows

  • JAWS: Virtual Cursor off in editor; on in published preview for heading navigation.

  • NVDA: Focus Mode in editor; Browse Mode in published form.

  • VoiceOver: direct interaction in editor; heading navigation in published form.

Part 19 - Braille and Mobile

  • Braille follows the active screen reader; test labels, option selection, edit fields, and routing.

  • Mobile can be used to complete Forms; desktop is usually easier for building complex forms.

  • Test forms on at least one mobile screen reader when the audience will use phones.

Part 20 - Security and Privacy

  • Collect only data you genuinely need.

  • Explain why sensitive information is requested.

  • Use organization-approved accounts for student/client/employee data.

  • Review who can edit the form and who can view response spreadsheets.

  • File-upload questions can collect sensitive documents; use them only with clear authorization.

Part 21 - Troubleshooting

Editor shortcuts do not work

  1. Move focus out of question-title edit fields when the shortcut requires a non-edit field.
  2. Turn off JAWS/NVDA browse mode.
  3. Press Ctrl+/ to confirm current command.

Published form is hard to navigate

  1. Add descriptive sections.
  2. Rewrite question labels.
  3. Avoid grids.
  4. Test heading navigation.

Respondent cannot open form

  1. Check publishing status.
  2. Check sign-in/domain restrictions.
  3. Check link.

Response sheet is confusing

  1. Review form question order.
  2. Use clear question titles.
  3. Avoid frequently renaming questions after collection begins.
