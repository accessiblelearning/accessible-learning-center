How to use this manual

Use these sections after learning basic screen-reader, Windows, web, and document skills. Each section emphasizes safe practice, keyboard orientation, clear verification, and protecting private information.

Version reminder: Application layouts and commands change. Confirm current labels with the official product documentation linked below and listen to the accessible name of each control.

1. Outlook and accessible email

Build a reliable workflow around four locations: the folder list, message list, reading area, and message editor. Before acting, identify which location has focus and whether you are using classic Outlook, new Outlook, or Outlook on the web.

Core workflow

  1. Confirm the account and current folder before reading or moving messages.
  2. Read the sender, subject, date, and attachment status before opening links or files.
  3. When composing, verify the To, Cc, Bcc, Subject, and message fields separately.
  4. Before sending, review recipients, attachments, private information, tone, and subject.
  5. Use search and folders to find messages; do not depend only on visual position.

Practice task: Using fictional addresses and information, draft a message, add a descriptive subject, attach a harmless practice file, review every field, and save it as a draft without sending it.

2. Zoom, Microsoft Teams, and Google Meet

Meeting applications combine audio controls, participant information, chat, reactions, captions, screen sharing, and dialogs. Learn each platform's current control names instead of assuming one application's shortcut works in another.

  1. Join with microphone muted unless the meeting instructions say otherwise.
  2. Confirm the meeting title and audio connection before speaking.
  3. Locate mute, participants, chat, captions, raise hand, and leave controls.
  4. Before sharing, close private windows and confirm the exact window or screen selected.
  5. When hosting, explain how participants can request help and access shared information without seeing the screen.

Practice task: Create a meeting-readiness checklist that separates participant, presenter, and host responsibilities. Do not record anyone without permission.

3. OneDrive, Dropbox, and cloud-sharing safety

Cloud storage introduces ownership, synchronization, link permissions, version history, and shared folders. “In my folder” does not always mean “owned only by me.”

  1. Identify the active account, file owner, storage location, and synchronization status.
  2. Use specific filenames and verify the destination folder before moving or saving.
  3. Choose the narrowest sharing permission that completes the task.
  4. Check whether a link allows viewing or editing and whether it expires.
  5. Keep a separate backup before reorganizing a large synchronized folder.

Practice task: Write a sharing plan for a fictional document. State who owns it, who needs access, which permission they need, and how access will be removed.

4. Google Drive, Gmail, Forms, and Classroom

These tools share an account but use different navigation models. Confirm the product, account, mode, and current region before using a remembered shortcut.

  • Drive: distinguish My Drive, Shared with me, shortcuts, and files owned by someone else.
  • Gmail: review conversation grouping, recipients, scheduled sending, attachments, and suspicious links.
  • Forms: use real question labels, instructions, required-state announcements, and a confirmation message.
  • Classroom: distinguish assignment instructions, attached resources, private comments, class comments, and submission status.

Practice task: Design a fictional accessible form with five clearly labeled questions, useful instructions, and a confirmation message. Test it using only the keyboard and a screen reader.

5. Accessible audio recording and editing

Audio editing requires awareness of the selected time range, play position, track, recording source, and output format. Save an editable project before exporting a listening copy.

  1. Record a short fictional script and stop before editing.
  2. Play it from the beginning and identify unwanted silence or noise.
  3. Select a small range, verify its boundaries, and edit only after making a backup.
  4. Save the project in the application's editable format.
  5. Export a separate audio file and verify its duration, filename, and playback.

Practice task: Produce a 30-second spoken instruction with a clear beginning and ending. Keep both the editable project and exported audio.

6. NotebookLM, Be My Eyes, and AI-assisted access

AI can summarize sources or describe images, but it can omit, invent, or misidentify important information. Treat its output as a draft interpretation.

  1. Use only material you are authorized to share.
  2. Ask the tool to distinguish observations from interpretations.
  3. Verify names, numbers, dates, links, labels, and safety-critical details.
  4. Use a human or authoritative source when an error could cause harm, disclosure, or loss.
  5. Record what was checked and what remains uncertain.

Practice task: Compare an AI summary with its original public source and document three accurate points, one omission, and any unsupported statement.

7. Diagnose before restarting

When access breaks, separate four possible causes: keyboard focus, screen-reader mode or settings, the application, and the computer or connection.

  1. Pause and protect unsaved work.
  2. Ask the screen reader for the current window, focused control, or status.
  3. Try one reversible check and observe one result.
  4. Compare another window, browser, or screen reader only when it will add useful evidence.
  5. Restart or reinstall only after simpler checks fail and important work is safe.
